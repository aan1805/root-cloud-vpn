# Root Cloud — централизованное управление фермой AmneziaVPN

## Описание
Root Cloud — это веб-панель для управления несколькими серверами AmneziaVPN, с балансировкой трафика через HAProxy. Система позволяет:
- Добавлять/удалять серверы с поддержкой AmneziaWG, XRay Reality, OpenVPN.
- Управлять клиентами (лимиты по времени и трафику).
- Автоматически настраивать HAProxy для распределения нагрузки.
- Собирать статистику и отображать её на дашборде.
- Использовать REST API для интеграции с внешними системами.

## Архитектура
- **Backend**: Flask + Gunicorn
- **База данных**: PostgreSQL
- **Брокер задач**: Redis + Celery
- **Балансировщик**: HAProxy (может быть установлен отдельно или в контейнере)

## Требования
- Docker и Docker Compose (для запуска в контейнерах)
- Минимум 2 ГБ RAM, 20 ГБ дискового пространства
- Открытые порты: 80 (HTTP), 443 (HTTPS), 5000 (API), а также порты VPN протоколов (51820/udp, 443/tcp и др.)

## Быстрый старт (Docker Compose)

### 1. Клонирование репозитория
```bash
git clone https://github.com/aan1805/root-cloud.git
cd root-cloud
```

### 2. Настройка переменных окружения
Скопируйте пример файла .env и отредактируйте под свои нужды:
```bash
cp .env.example .env
nano .env
```

Обязательно измените `SECRET_KEY` и пароль PostgreSQL на надёжные.

### 3. Запуск
```bash
docker-compose up -d
```

При первом запуске будут созданы и инициализированы контейнеры. Подождите минуту.

### 4. Создание администратора

Перейдите по адресу http://ваш-сервер/auth/register и создайте первого администратора. (Этот маршрут доступен только при отсутствии пользователей.)

### 5. Доступ к панели

После регистрации войдите в систему. Дашборд доступен по главному URL.

## Настройка HAProxy (балансировщик)

### Вариант А: HAProxy на отдельном сервере (рекомендуется)
1. Установите HAProxy на отдельный сервер (или ВМ) с доступом по SSH.
2. Убедитесь, что HAProxy скомпилирован с поддержкой stats socket (обычно включено).
3. В панели Amnezia Farm перейдите в раздел HAProxy → Добавить сервер, укажите данные для SSH-доступа.
4. Создайте бэкенды для каждого протокола (например, awg_backend, xray_backend).
5. При добавлении серверов Amnezia с установленными протоколами они автоматически синхронизируются с HAProxy.

### Вариант Б: HAProxy в контейнере (экспериментально)
Вы можете добавить сервис HAProxy в ваш docker-compose.yml, но учтите, что для работы с UDP могут потребоваться особые настройки сети.

## REST API
API доступно по адресу `http://ваш-сервер/api/v1/`. Документация (Swagger) — `/apidocs`.

## Аутентификация
Требуется Bearer токен. Токены создаются в разделе Настройки → API токены. Для веб-интерфейса токен выдаётся автоматически.

### Примеры запросов

```bash
# Получить список серверов
curl -H "Authorization: Bearer <токен>" http://localhost:5000/api/v1/servers

# Создать клиента
curl -X POST -H "Authorization: Bearer <токен>" -H "Content-Type: application/json" \
  -d '{"name":"test","server_id":1,"protocol_id":2}' \
  http://localhost:5000/api/v1/clients
```

## Управление без Docker (ручная установка)

### Зависимости
- Python 3.10+
- PostgreSQL 15+
- Redis 7+
- (Опционально) Nginx, HAProxy

### Установка

1. Создайте виртуальное окружение и установите зависимости:
```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```
2. Настройте БД и переменные окружения (см. .env.example).
3. Примените миграции: `flask db upgrade`.
4. Запустите Gunicorn:
```bash
gunicorn --bind 0.0.0.0:5000 run:app
```
5. Запустите Celery worker и beat (в отдельных терминалах или через systemd):
```bash
celery -A app.celery_app.celery worker --loglevel=info
celery -A app.celery_app.celery beat --loglevel=info
```

## Масштабирование

- Для увеличения пропускной способности можно запустить несколько экземпляров веб-приложения за балансировщиком (например, nginx).
- Celery worker'ы можно масштабировать горизонтально, указав общий брокер Redis.

## Безопасность

- Всегда используйте HTTPS в production. Настройте SSL-сертификат (Let's Encrypt) для nginx.
- Храните секреты в переменных окружения, не коммитьте .env файл.
- Регулярно обновляйте образы и зависимости.
- Ограничьте доступ к портам административной панели (например, через firewall).

## Устранение неполадок

### Ошибка подключения к БД

Проверьте, что контейнер db запущен и доступен по имени `db` внутри сети Docker.

### Celery задачи не выполняются

Убедитесь, что Redis запущен, и в логах worker'а нет ошибок. Проверьте подключение к Redis.

### HAProxy не видит серверы

Проверьте, что на серверах Amnezia установлены соответствующие протоколы и они имеют статус `installed`. Проверьте SSH-доступ к HAProxy-серверу.
